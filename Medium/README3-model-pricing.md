## 快取寫入（Prompt Caching Write）是什麼？

### 概念

當你重複呼叫 AI API 時，如果每次都把一段很長的「固定內容」（例如系統提示、文件、程式碼庫）重新送入模型，就要重複付全價。

**Prompt Caching（提示詞快取）** 的機制是：第一次把這段固定內容「寫入快取」，之後再使用時直接「讀取快取」，速度更快、費用更低。

- **快取寫入（Cache Write）**：第一次把內容存入快取，費用略高於普通輸入
- **快取讀取（Cache Read）**：之後呼叫時從快取讀取，費用大幅降低

---

### 舉例說明

假設你在開發一個法律 AI 助理，每次呼叫都要附上一份 **10 萬字的法律文件** 作為背景知識：

**沒有快取的情況：**

```text
呼叫 1：[10萬字法律文件] + 問題A  → 付 10萬字輸入費
呼叫 2：[10萬字法律文件] + 問題B  → 付 10萬字輸入費
呼叫 3：[10萬字法律文件] + 問題C  → 付 10萬字輸入費
```

每次都付全額，非常浪費。

**有快取的情況：**

```text
呼叫 1：[10萬字法律文件] + 問題A  → 付「快取寫入」費（略貴，但只付一次）
呼叫 2：[快取] + 問題B             → 付「快取讀取」費（非常便宜）
呼叫 3：[快取] + 問題C             → 付「快取讀取」費（非常便宜）
```

---

### 用 MiniMax M2.7 的定價來算

| 費用類型 | 每百萬 tokens |
|---------|-------------|
| 普通輸入 | $0.30 |
| 快取寫入 | $0.375（比普通輸入貴 25%） |
| 快取讀取 | $0.06（比普通輸入便宜 80%） |

**為什麼快取寫入比普通輸入貴？** 因為系統需要額外的計算資源來處理並儲存這段內容，就像複印一份文件存檔，需要多花一點時間和成本。

**長期下來划算嗎？** 非常划算。只要同一段內容被讀取**超過 2～3 次**，總費用就會遠低於每次重新輸入。這對於需要大量重複呼叫的 AI Agent、客服系統、**程式碼分析工具**等場景特別有用。
